# typed-notion-cli

[![npm version](https://badge.fury.io/js/typed-notion-cli.svg)](https://badge.fury.io/js/typed-notion-cli)
[![TypeScript](https://img.shields.io/badge/%3C%2F%3E-TypeScript-%230074c1.svg)](http://www.typescriptlang.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

> **Professional CLI tool** for generating type-safe TypeScript schemas from Notion data sources with advanced automation and CI/CD integration.

## Key Features

- **One-Command Setup**: Initialize projects with `typed-notion init` - zero configuration required
- **Auto Schema Generation**: Pull type-safe schemas directly from Notion databases using latest 2025-09-03 API
- **Formula Type Safety**: Intelligent handling of complex formulas with `unknown` fallbacks for safety
- **CI/CD Ready**: Built-in validation commands for continuous integration pipelines
- **Legacy Migration**: Seamless migration from old database ID format to modern data sources
- **Performance Optimized**: Built-in monitoring, bundle optimization, and comprehensive logging
- **Hacker-Style Interface**: Beautiful ANSI-styled CLI with boot sequences and progress animations

## Installation

```bash
# Global installation (recommended)
npm install -g typed-notion-cli

# Project-specific installation
npm install --save-dev typed-notion-cli
```

## Quick Start

Generate type-safe schemas from your Notion databases in 3 simple steps:

```bash
# 1. Initialize your project
npx typed-notion init

# 2. Generate schemas from Notion
npx typed-notion pull

# 3. Validate schemas (perfect for CI/CD)
npx typed-notion validate
```

That's it! Your TypeScript schemas are now generated and ready to use.

## Core Commands

### 🚀 Project Initialization

```bash
typed-notion init [options]

# Interactive setup with guided prompts
typed-notion init

# Force overwrite existing configuration
typed-notion init --force

# Non-interactive mode (perfect for automation)
typed-notion init --non-interactive --token YOUR_NOTION_TOKEN
```

**What it creates:**

- `typed-notion.config.ts` - Project configuration
- `.env` - Environment variables template
- Project structure validation
- TypeScript integration setup

### 📥 Schema Generation

```bash
typed-notion pull [options]

# Generate schemas from all configured databases
typed-notion pull

# Generate from specific data source
typed-notion pull --data-source src_abc123

# Force overwrite existing schema files
typed-notion pull --force

# CI/CD mode (no interactive prompts)
typed-notion pull --non-interactive
```

**Features:**

- **Auto-discovery**: Automatically finds available Notion data sources
- **Type inference**: Generates precise TypeScript types for all property types
- **Formula safety**: Handles complex formulas with proper type fallbacks
- **Prettier integration**: Auto-formats generated code
- **Progress tracking**: Real-time progress with beautiful animations

### ✅ Schema Validation

```bash
typed-notion validate [options]

# Validate all schemas against current Notion state
typed-notion validate

# Auto-fix minor differences
typed-notion validate --fix

# Exit with code 1 on differences (perfect for CI)
typed-notion validate --strict
```

**Perfect for:**

- **Continuous Integration**: Ensure schemas stay synchronized
- **Team Development**: Catch schema drift early
- **Production Deployments**: Validate before releases

## Configuration

### Project Configuration (`typed-notion.config.ts`)

```typescript
import { defineConfig } from 'typed-notion-cli';

export default defineConfig({
  // Output file for generated schemas
  output: './src/lib/notion-schema.ts',

  // Database configurations
  databases: {
    projects: {
      dataSourceId: 'src_abc123def456', // Modern format (recommended)

  // Code formatting options
  formatting: {
    usePrettier: true,
    prettierConfig: './.prettierrc',
  },

  // API retry configuration
  retry: {

    backoffMs: 1000,
  },
});
```

## Generated Schema Example

The CLI generates clean, type-safe TypeScript schemas:

```typescript
// Auto-generated by typed-notion-cli
import { z } from 'zod';

/**
 * Projects Database Schema
 * Generated from Notion data source: src_abc123def456
 * Last updated: 2024-12-05T10:30:00Z
 */

export const ProjectsSchema = z.object({
  id: z.string(),
  title: z.string(),
  status: z.enum(['Planning', 'In Progress', 'Complete', 'On Hold']),
  priority: z.enum(['Low', 'Medium', 'High', 'Critical']),
  assignee: z.array(
    z.object({
      id: z.string(),
      name: z.string(),
      email: z.string().email(),
    })
  ),
  dueDate: z.string().datetime().nullable(),
  tags: z.array(z.enum(['Frontend', 'Backend', 'Design', 'Bug', 'Feature'])),

  // Formula properties (safely handled)
  progress: z.number().nullable(), // Calculated: Completed tasks / Total tasks
  isOverdue: z.boolean().nullable(), // Formula with proper type safety

  // Rollup properties (auto-inferred types)
  totalTaskCount: z.number().nullable(),
  lastUpdated: z.string().datetime().nullable(),
});

export type Project = z.infer<typeof ProjectsSchema>;

// Helper functions for working with the schema
export const createProject = (
  data: Omit<Project, 'id' | 'progress' | 'isOverdue' | 'totalTaskCount' | 'lastUpdated'>
) =>
  ProjectsSchema.omit({
    id: true,
    progress: true,
    isOverdue: true,
    totalTaskCount: true,
    lastUpdated: true,
  }).parse(data);

export const validateProject = (data: unknown): Project => ProjectsSchema.parse(data);

export const isValidProject = (data: unknown): data is Project =>
  ProjectsSchema.safeParse(data).success;
```

```yaml
    steps:
      - uses: actions/checkout@v4
```

## Troubleshooting

### Common Issues

**Token Issues:**

```bash
# Verify your token is correctly set
echo $NOTION_TOKEN

# Regenerate token at https://www.notion.so/my-integrations
typed-notion init --force
```

**Permission Errors:**

- Ensure your integration has access to the databases
- Share databases with your integration in Notion
- Check that database IDs are correct

**Schema Validation Failures:**

```bash
# Get detailed validation information
typed-notion validate --verbose

# Auto-fix minor differences
typed-notion validate --fix

# Force regenerate schemas
typed-notion pull --force
```

## Supported Property Types

The CLI supports **100% of Notion property types** with intelligent type inference:

| Notion Property  | TypeScript Type  | Validation            | Notes                  |
| :--------------- | :--------------- | :-------------------- | :--------------------- |
| **Title**        | `string`         | Required, non-empty   | Primary identifier     |
| **Rich Text**    | `string`         | Text content          | Plain text extraction  |
| **Number**       | `number \| null` | Numeric values        | Nullable by default    |
| **Select**       | `enum`           | Exact option matching | Type-safe unions       |
| **Multi-select** | `enum[]`         | Array of options      | Type-safe arrays       |
| **Date**         | `string \| null` | ISO date format       | DateTime support       |
| **Checkbox**     | `boolean`        | True/false values     | Boolean logic          |
| **People**       | `User[]`         | Notion user objects   | Full user details      |
| **Files**        | `File[]`         | File attachments      | URL and metadata       |
| **URL**          | `string \| null` | Valid URL format      | URL validation         |
| **Email**        | `string \| null` | Email validation      | RFC compliant          |
| **Phone**        | `string \| null` | Phone numbers         | International format   |
| **Relation**     | `string[]`       | Array of page IDs     | Cross-database refs    |
| **Rollup**       | `T \| null`      | **Auto-inferred**     | From source property   |
| **Formula**      | `T \| null`      | **Safe fallback**     | `unknown` when unclear |

### Formula Type Safety

The CLI uses advanced heuristics to determine formula return types:

```typescript
// Safe type inference
totalBudget: z.number().nullable(),     // SUM rollup
isComplete: z.boolean().nullable(),     // Boolean formula
statusLabel: z.string().nullable(),     // String concatenation

// Ambiguous formulas default to unknown for safety
```

## API Reference

### CLI Commands

- `typed-notion init [options]` - Initialize new project with configuration

- `NOTION_TOKEN` - Required integration token
- `NOTION_API_VERSION` - API version (defaults to 2025-09-03)
